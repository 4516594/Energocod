# Руководство по развёртыванию

Платформа — статический сайт плюс опциональный бэкенд Supabase. Публикация и бэкенд укладываются в бесплатные тарифы. Ниже два пути: быстрый (только статика, демо-режим) и полный (статика + Supabase + Telegram).

## Вариант A. Только статика (демо-режим)

Данные хранятся в браузере, бэкенд не нужен. Годится для показа и тестовой среды.

### GitHub Pages

1. Создайте репозиторий и загрузите в него содержимое папки `platform_v4/` (файл `index.html` должен лежать в корне публикуемой ветки или в папке `/docs`).
2. Settings → Pages → Source: ветка (например `main`), папка `/root` или `/docs`.
3. Через минуту сайт доступен по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

### Cloudflare Pages (альтернатива)

1. Создайте проект Pages, укажите репозиторий или загрузите папку `platform_v4/` через drag-and-drop.
2. Build command оставьте пустым (сборка не нужна), output directory — корень с `index.html`.

## Вариант B. Production-бэкенд Supabase

Добавляет постоянное хранилище, вход по e-mail и паролю, построчную безопасность (RLS) и уведомления.

### 1. Создать проект Supabase

1. Зарегистрируйтесь на supabase.com, создайте новый проект (Free-тариф). Запомните пароль базы.
2. В Project Settings → API возьмите `Project URL` и `anon public` ключ, они понадобятся в платформе.

### 2. Выполнить схему

1. Dashboard → SQL Editor → New query.
2. Вставьте целиком содержимое `supabase/schema.sql` и нажмите Run. Схема создаёт таблицы, перечисления, индексы, триггеры (автопрофиль при регистрации, событие и уведомление при смене вехи) и политики RLS.

### 3. Подключить платформу

1. Опубликуйте статику по Варианту A.
2. Войдите администратором, откройте «Администрирование» → «Интеграции».
3. Введите Supabase URL и anon key, нажмите «Сохранить реквизиты», затем «Подключить Supabase». Индикатор должен показать «Supabase подключён».

После этого регистрация и вход идут через Supabase Auth, данные хранятся в Postgres. Выбор адаптера запоминается: при следующей загрузке подключение восстанавливается автоматически.

### 4. Первый администратор в Production

Демо-профили есть только в LocalAdapter. В Supabase зарегистрируйте пользователя через экран регистрации платформы, затем в Dashboard → Table Editor → `profiles` смените его `role` на `admin`. Дальше пользователями управляйте из админ-панели.

### 5. Уведомления в Telegram

1. Создайте бота через @BotFather, впишите токен в «Интеграции».
2. Разверните серверную функцию рассылки:

   ```
   supabase functions deploy notify --no-verify-jwt
   ```

3. Заполните `telegram_chat_id` в профилях участников (как узнать chat_id — в `supabase/functions/notify/README.md`).
4. Отправка: кнопка «Отправить очередь» в админ-панели либо cron в Supabase (Database → Cron) с периодическим вызовом функции.

## Проверка после развёртывания

Прогоните смоук-тест логики локально (`node tests/smoke.test.js`) и пройдите ручной чек-лист экранов по ролям и языкам из `docs/TEST_CHECKLIST.md`.

## Обработка персональных данных

Онлайн-версия обрабатывает персональные данные пользователей (e-mail, ФИО, компания). При запуске публичной версии по 152-ФЗ требуется опубликовать политику обработки персональных данных. Правки регламента доступа и политика ПД — отдельный шаг проекта (P6).
