# Руководство администратора

Роль `admin` открывает вкладку «Администрирование» и позволяет менять все параметры платформы из интерфейса, без правки кода. Изменения настроек версионируются: прежняя версия уходит в историю, её видно в разделе «История версий настроек».

Вход администратора по умолчанию: `admin@energocod.ru`, демонстрационный пароль `energocod`. В Production смените пароль через Supabase Auth (см. DEPLOY_GUIDE).

## Разделы админ-панели

**Настройки расчёта (константы-ориентиры).** Тарифы и доли, на которых строится финансовая модель конфигуратора: техприсоединение (млн ₽/МВт), множитель за второй ввод, стоимость ДГУ и ИБП, доли эксплуатационных затрат, горизонт LCOE, ставка НДС. Конфигуратор перечитывает эти значения при каждом открытии, поэтому правки применяются сразу.

**Веса скоринга площадок.** Удельный расход газа и веса девяти признаков (газ, ГРС, сеть, ВОЛС, второй ввод, ВРИ, обременения, статус, транспорт) для двух профилей питания: собственная генерация (ГПУ) и сеть.

**Диапазоны и значения по умолчанию бегунков.** Для каждого параметра конфигуратора: минимум, максимум, шаг и значение по умолчанию.

**Пользователи и роли.** Смена роли, блокировка и разблокировка, добавление пользователя, а также поле «Telegram chat_id» — адрес для уведомлений (см. ниже). Кнопка «Сбросить все настройки к исходным» возвращает заводские значения; история версий при этом сохраняется.

**Журнал посещений.** Последние 60 событий: время, пользователь, роль, раздел, тип события (вход, переход, смена роли). Виден только администратору.

**Интеграции.** Реквизиты Production-бэкенда и уведомлений: Supabase URL, anon key, токен Telegram-бота. Кнопка «Подключить Supabase» переводит платформу с демо-режима на Postgres; «Вернуться в демо-режим» отключает бэкенд, не стирая реквизиты. Индикатор показывает активный источник данных и последнюю ошибку подключения.

**Уведомления (Telegram).** Очередь уведомлений и кнопка «Отправить очередь». Изменение готовности вехи проекта ставит уведомление ответственной роли в очередь. Отправка идёт в Telegram по токену бота тем участникам, у кого задан chat_id. В таблице видно время, канал, получателя, тему, текст и статус (в очереди, отправлено, ошибка) с причиной ошибки.

## Настройка уведомлений в Telegram

1. Создайте бота через @BotFather (команда `/newbot`), получите токен и впишите его в «Интеграции» → «Telegram bot token».
2. Каждый участник, который должен получать уведомления, пишет боту `/start`. Узнайте его chat_id (через `https://api.telegram.org/bot<токен>/getUpdates` или бота @userinfobot) и впишите в столбец «Telegram chat_id» его профиля.
3. В демо-режиме отправка идёт прямо из браузера кнопкой «Отправить очередь». В Production рассылку выполняет серверная функция `notify` (см. `supabase/functions/notify/README.md`).

Подробности по боту и chat_id — в `supabase/functions/notify/README.md`.

## Переключение на Production-бэкенд

Один раз выполните `supabase/schema.sql` в SQL-редакторе проекта Supabase, затем введите URL и anon key в «Интеграции» и нажмите «Подключить Supabase». Пошагово — в `DEPLOY_GUIDE.md`. После подключения данные хранятся в Postgres с построчной безопасностью (RLS): каждый видит своё, администратор — всё.
