# Ручной чек-лист приёмки

Проверка платформы перед публикацией. Отмечайте пройденные пункты. Демо-вход: любой из профилей роли, пароль `energocod`; администратор `admin@energocod.ru`. Под ролью admin можно просматривать платформу от имени любой роли (селектор роли в шапке).

## 1. Авторизация

- [ ] Вход по e-mail и паролю; неверный пароль отклоняется с сообщением.
- [ ] Регистрация нового пользователя (e-mail, ФИО, компания, роль, пароль).
- [ ] Быстрый вход демо-профилем.
- [ ] Заблокированный пользователь не входит.
- [ ] Кнопка «Выйти» возвращает на экран входа.

## 2. Экраны по ролям

Пройдите каждую вкладку под каждой ролью. У роли видны только её вкладки; у admin дополнительно «Администрирование» и селектор роли.

| Вкладка | Что проверить |
|---|---|
| Кабинет (dash) | сводка соответствует роли, без ошибок в консоли |
| Каталог активов (assets) | карточки, скоринг площадок отображаются |
| Карта размещения (map) | карта рисуется, зум и тултипы работают |
| Конфигуратор (calc) | бегунки, пересчёт финмодели, пресеты |
| Заявки и проекты (deals) | список заявок, добавление, кнопки вех и контактов |
| Участники (members) | реестр, фильтр по типу, кандидаты |
| НПА и стандарты (npa) | список НПА, карточки открываются |
| Администрирование (admin) | только у admin, все разделы (см. п.5) |

Роли для прогона: uk, customer, investor, land, grid, fiber, ec, dc, it, op, admin.

## 3. Языки интерфейса

Для каждого языка (RU, EN, 中文) переключите язык в шапке и проверьте:

- [ ] Навигация переведена: вкладки, названия и подсказки ролей, метки шапки, подвал.
- [ ] При EN/中文 показывается пометка о том, что контент каталогов остаётся русским.
- [ ] Выбор языка сохраняется после перезагрузки (пишется в профиль).

## 4. Вехи и уведомления (P3.1–P3.3)

- [ ] На карточке заявки открывается окно «Вехи проекта»: 9 этапов по шаблону.
- [ ] УК и admin правят любые вехи; ответственная роль правит только свои этапы; остальные — просмотр.
- [ ] Изменение готовности, срока, исполнителя фиксируется в журнале изменений.
- [ ] Общий процент готовности пересчитывается.
- [ ] После смены готовности в админ-панели («Уведомления») появляется запись в очереди для ответственной роли.
- [ ] Кнопка «Отправить очередь» при заданном токене бота и chat_id отправляет сообщение в Telegram, статус меняется на «отправлено».
- [ ] Без токена или без chat_id запись помечается ошибкой с понятной причиной.

## 5. Журнал результативных контактов (P3.2)

- [ ] Кнопка «Передать результативные контакты» пишет контакты по профилям заявки (статус «передан»).
- [ ] Кнопка «Откликнуться» участника фиксирует отклик.
- [ ] У УК/admin открывается «Журнал контактов» по заявке.
- [ ] Экспорт CSV открывается в Excel корректно (разделитель «;», кириллица без искажений).

## 6. Администрирование (только admin)

- [ ] Правка констант расчёта меняет результат конфигуратора.
- [ ] Правка весов скоринга и диапазонов бегунков сохраняется, версия настроек растёт.
- [ ] Смена роли и блокировка пользователя работают; добавление пользователя.
- [ ] Поле «Telegram chat_id» сохраняется в профиле.
- [ ] Журнал посещений заполняется при переходах.
- [ ] «Сбросить все настройки к исходным» возвращает значения, история сохраняется.
- [ ] История версий настроек отображает изменения.

## 7. Переключение адаптера (демо ↔ Supabase)

- [ ] В демо-режиме индикатор источника данных — «Демо-режим (LocalAdapter)».
- [ ] После ввода корректных Supabase URL/ключа и «Подключить Supabase» индикатор — «Supabase подключён».
- [ ] «Вернуться в демо-режим» возвращает LocalAdapter, реквизиты не стираются.
- [ ] После перезагрузки выбранный адаптер восстанавливается автоматически.

## 8. Смоук-тест логики

- [ ] `node tests/smoke.test.js` завершается без падений (0 FAIL).
